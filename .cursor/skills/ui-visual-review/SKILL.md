# Визуальный разбор интерфейса

Не считать вёрстку готовой по CSS. Нужны **пиксели**: живой URL или локальный kit.

## Когда включать

Пользователь просит улучшить дизайн, меню, сетку, графику, «как выглядит», или правит HTML/CSS в `design-system/grangranita/`.

## Шаги

1. Открыть страницу (продакшен или `examples/*.html`).
2. Снять **два кадра**: ширина ~1440 и ~390. Для длинной страницы — ещё один кадр середины (каталог / работы).
3. Смотреть картинку, не DOM:
   - первый экран: что якорь — логотип, оффер, телефон, обрезок слайдера?
   - меню: одна линия / перенос / бургер; активный пункт; не перекрывает контент
   - блоки: ритм отступов, дыры в сетке, H1-простыня до картинок
   - графика: акварель vs силуэт vs фото; обрезка; промо-скотч на камне
   - CTA: сколько языков кнопок на одном экране (тёмная / зелёная / контур)
   - мобиле: tap target ≥ 44px, горизонтальный скролл пилюль с hint
4. Список: проблема → кадр/блок → приоритет P0/P1/P2 → правка.
5. После правок — повторный скрин тех же ширин.

## Тон «Грань Гранита»

См. `design-system/grangranita/IMPROVEMENTS.md` и `.cursor/rules/grangranita-design-system.mdc`.

Мемориальный сервис: не кричать скидками на первом экране. Primary — гранит, не салатовый.

## Артефакты

Скриншоты класть в `design-system/grangranita/audit/` только если это разбор продакшена. Kit не требует git-картинок каждого шага.
